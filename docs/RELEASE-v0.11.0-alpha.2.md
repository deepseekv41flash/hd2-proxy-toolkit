# v0.11.0-alpha.2 — 修：底栏「引擎运行中」时 hosts 行仍说「未运行」

> 2026-11-26 · 预发布（alpha）· 纯 bug 修复（`0.11.0-alpha.1` → `0.11.0-alpha.2`）

## 现象（实机）

底栏与右上角显示**引擎运行中**、状态卡是「改写」、证书剩 129.0 小时，但按钮下方那一行仍是：

```
hosts：→ 100.67.88.219 但引擎未运行 ⇒ 游戏会连不上；点「恢复直连（hosts）」
```

同一屏两处结论互相矛盾（而且当时游戏其实是能连的）。

## 根因（两层）

1. **判定口径错了**：`_render_hosts_line` 用 `status["mode"]` 判断"引擎是否在跑"，可 `mode`
   在**改写模式下是缺省/None**（只有「直通」才显式给出 passthrough）⇒ `bool(None)` 恒为 False，
   于是永远说"未运行"。底栏与状态卡用的是 `client.running()`，两者不同源。
2. **刷新时机错了**：那一行只在节流（≥2.5 s）的现场检查里重算，**引擎启停后不会跟着变**，
   所以即使判定对了，也可能长时间停在旧结论上。

## 修法

- 运行态改判 `client.running()`（与底栏/状态卡同源；客户端缺该方法时退回 `last_status`）；
- `on_status` 每次轮询都重刷这一行（含 `status is None` 的"未运行"分支）：
  - 引擎在跑 → `hosts：→ <ip>（代理生效中；关掉引擎前请点「恢复直连」）`（绿）
  - 引擎停 → `hosts：→ <ip> 但引擎未运行 ⇒ 游戏会连不上；点「恢复直连（hosts）」`（红）
- 顺带去掉了那行里的 Markdown 星号（`**引擎未运行**` 在 Tk 标签里会原样显示）。

## 验证

- 单测 **+1** 回归：`last_status` 里**故意不放** `mode` 字段（正是实机那种情况），
  `client.running()` 为真时必须显示「代理生效中」、且不得出现「引擎未运行」。全量 **790 passed、GATE=PASS**。
- 该测试在修复前会失败（旧逻辑判 False）。

## 二、修复 1：HD2 20 位别名跨账号残留

**现象**（`.bak` 实证）：换号瞬间 `GetMotd` 先到、`GetMessages` 未到，上一账号的 HD2 id 被写进新档：

```json
{"hd2_account_id": "11893343864225233967", "steam_id": "76561199881579811", ...}
```

（主号别名 + 空号 SteamID64）约 1 分钟后才被 `GetMessages` 纠正；切回主号时同样会把空号别名短暂写进主号档。

**修复**：别名只认**本局观测值**（`_hd2_session`）——

- `GetMotd` 先到 → 新档 `hd2_account_id` 写 `null`，`GetMessages` 到后再补；
- Steam 号变化时清空旧账号别名，切回已有档**不覆盖**其正确别名；
- `GetMessages` 先到且属于别的账号时，不写进预绑定档（丢掉属于上一局的那对预绑定身份）。

## 三、修复 2：首屏预合并的「显示回声」污染（新增 `saves.preverify_merge`）

**现象**：空号段 `PUT /Achievements` 上报 `[{6:1681},{8:386301},{17:4290},{24:2926}]` ——
明显是主号账本（1680/386242/4290/2925）被首屏合并展示后，客户端把"看到的数"加增量**回显上报**，
再被账本记成空号自己的成就。根因：预绑定 merge 在身份校验前就把上一档账本合进了响应。

**修复**：`saves` 新增三档策略（**默认 `safe`**）：

| 模式 | 身份未校验时合并什么 | 用途 |
|---|---|---|
| **`safe`（默认）** | 只合并**服务端自算、客户端不会回显**的字段（经验 / 包进度 / onboarding 等） | 官方服务器换号不污染 |
| `full` | 全合并（含成就 / 统计 / 库存） | `upstreamTest`、mock、自建服自动启用（「服务端给得少 ⇒ 存档层兜底」仍可验证） |
| `off` | 一律不合并 | 极端保守 |

- 换号告警同时补一句「本局首屏曾按旧档合并 N 处 —— 显示可能偏高，重启纠正」，把显示窗口说清；
- README「已知限制」表述修正：同机换号时**整局**可能沿用旧档合并视图（不止首屏，客户端不重取），
  重启纠正；`safe` 已阻断其中的成就回声污染路径。

## 四、数据修复说明（本机）

- 主号档 `identity.hd2_account_id` 被上一版短暂写成空号别名 → 下次 `GetMessages` 会自愈；
  若一直没到（未开邮箱/未进相关界面），停止引擎后按已知值手工纠正即可（`11893343864225233967`）。
- 空号档：本局增量按设计整档回滚（会话基准），脏档全文在 `runtime/saves/_orphan/` 可审计；
  服务端仍持有空号这一局的真实进度，本机账本回滚不影响服务端。

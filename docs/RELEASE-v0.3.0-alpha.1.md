## 为什么做这个

443 被占用时游戏「与服务器通讯时出错」、hosts 被加速器注释、本机 IP 变了导致 hosts 指向旧 IP……
这些现场问题以前只能等引擎启动失败后翻日志看，或者进游戏报错再回来猜。本版把它们搬到
「点启动引擎之前」和「总览页一眼可见」：

## 本版新增（P0 四项）

### 1. 启动前端口预检

点「启动引擎」时先检查 **443（代理）/ 8080（CRL）/ 17897（控制面）** 三个端口：

| 状态 | 含义 | 处理 |
|---|---|---|
| `free` | 空闲 | 直接放行 |
| `ours` | 本工具引擎占用 | 正常（不会误报冲突） |
| `conflict` | 别人占用 | 弹窗列**进程名 + PID + 完整路径**，可选「换监听地址…」「仍然启动」「取消」 |

- `0.0.0.0` / `[::]` 通配绑定会单独提示：**换监听 IP 无效，必须关掉占用者**；
- 探测用 `SO_EXCLUSIVEADDRUSE` 独占试绑（`SO_REUSEADDR` 会误报空闲）；
- `netstat` 同时查 IPv4 与 IPv6，双栈 `[::]:443` 的占用者也能查到（第三方工具只查 IPv4，会漏）。

### 2. 「换监听地址」对话框

总览页冲突弹窗与设置页「换监听地址…」按钮共用：

- 候选**只列真实网卡 IPv4**（新版客户端拒绝 127.x 回环连接）；
- 每行标：443 占用状态、网卡名、是否虚拟网卡、「推荐」（默认路由出口 > 物理网卡 > 虚拟）；
- 应用后写回 profile 监听 IP（还需「保存/应用配置」+ 重新安装以重写 hosts，界面有提示）。

### 3. 系统自检 + 总览红字

新增 `engine/diagnostics.py`（`collect()` 跑探测、`evaluate()` 纯函数出告警、`format_text()` 人读文本）：

- **端口**：三态 + 占用者路径 + 通配标记；
- **hosts**：没有 / 被注释（加速器 hosts 保护）/ IP 与本机监听不一致 / 已生效 四态；
- **关键告警**：`hosts 已指向本机，但引擎没在运行` → 现在进游戏必报「与服务器通讯时出错」；
- **证书**：可用性、剩余小时（<12h 提醒续期）；
- **游戏进程**：在跑时提示「改代理/重装前先退游戏」。

总览页有 error/warn 时红字直读摘要，点「系统自检」看完整分节报告。

### 4. 游戏运行守卫

检测到 `helldivers2.exe` 在跑时，**启动/停止引擎**都会先弹确认：「可能掐断当前会话（卡登录 /
与服务器通讯时出错），建议先退游戏」。取消后引擎保持原状态。

## 已知限制（alpha）

- 换监听地址后**仍需重新安装**（重写 hosts）才生效 —— GUI 只负责写 profile 与提示，
  真安装/还原仍走一次 UAC 的 CLI 流程；
- 端口预检在「启动引擎」按钮路径生效；引擎已运行时不会重复预检；
- 引擎侧的上游偶发超时（多 IP 重试）仍是待办，未包含在本版。

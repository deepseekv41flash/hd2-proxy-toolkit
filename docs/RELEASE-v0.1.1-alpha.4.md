# v0.1.1-alpha.4 — 修复「附件」列表只显示 80 条（去掉列表截断，1176 条全量进列表）（2026-11-17）

> **alpha 预览版**：只修界面列表截断，不动数据与能力。按规则只动 `alpha.N`。

## 本版修了什么

用户报：「附件」tab 只有 **80** 项，但 `items.json` 里有 **1176** 条附件。

**根因：数据没丢，是列表截断。** `Catalogs.search_items()` 默认 `limit=80`（关键词搜索时 `limit=200`）：

- tab 初始填充只取前 80 条，计数标签还显示 `80/80`，看起来像「总共只有 80 条」；
- 列表上方的搜索框只在这 80（或搜索后的 200）条里过滤，宽泛关键词命中超过 200 条时仍会被截断。

**修复**：`search_items(limit=None)` = 不截断；四个 tab 与「目录追加」都装全量：

| tab | 条目数 |
|---|---:|
| 武器 | 24 |
| 附件 | **1176** |
| 外观 | 426 |
| 战备 | 30 |
| 目录追加 | 1671 |

- 计数标签显示真实总数（`1176/1176`）；
- 列表下方提示改为「本类共 N 条；上方搜索框在全部条目里过滤，"关键词 + 搜索" 走目录全量查询」。

性能：Tk Listbox 装 1.7k 条无压力，实测打开/切换 tab 无可感延迟。

## 验证

  列表可滚动浏览全部条目。

# v0.10.1-alpha.1 — 一键解锁全部物品（仅本机视图，给测试账号用）

> 2026-11-25 · 预发布（alpha）· 能力变更（`0.10.0-alpha.1` → `0.10.1-alpha.1`）

## 一句话

「本地账号」页新增 **「一键解锁全部物品」**：按物品目录把**在架、可拥有**的全部物品一次性注入本机库存视图
（约 **2.5k 行**），用于给测试账号准备"什么都有"的环境。**只改客户端收到的响应，不写服务端任何数据。**

## 为什么需要

内核/内存路线要在测试账号上验证物品相关行为，但账号本身物品不全会干扰结论。
走代理侧解锁（本机视图）不触碰服务端、也不改客户端内存，因此不会污染内存侧测量结果。

## 怎么用

1. 打开 **「本地账号」** 页（原「物品与战备」）；
2. 点顶栏 **「一键解锁全部物品」**（会弹确认框，显示将注入多少行、跳过了多少）；
3. 点右上角 **「应用配置」**（热更新到引擎，无需重启）；
4. 进游戏即可看到客户端侧"全部物品已拥有"。
5. 再点一次同一个按钮 = 关闭（恢复原样）。

也可直接改 profile（等价）：

```json
"inventory": {
  "unlock_all": true,
  "unlock_scope": []          // 空=全部可拥有类别；可收窄为 ["weapon","attachment",...]
}
```

命令行等价：`hd2proxy preview --profile <p>` 可离线看到会注入多少行（不开游戏）。

## 展开规则（`engine/item_catalog.py`）

数据源：`data/catalogs/items.json`（`/api/Progression/items` 全量行归档，3062 行）。

* 计入：`in_catalog=true` + 有 `mix_id` + 非 `currency` + 非 `default_owned`
* 跳过：不在架 **42** 行（注入了也看不到）、货币 **15** 行、空号默认拥有 **52** 行、无 mixId **367** 行
* 当前实际注入：**2586 行**（`amount=1`、`isDiscovered=false`，与既有单条注入同形）
* 去重：与用户已手动添加的行合并去重；客户端轮询重复请求不会重复注入（幂等）

可选收窄范围（`inventory.unlock_scope`）：`weapon` / `attachment` / `cosmetic` /
`stratagem` / `banner` / `booster` / `unknown`。校验不认识的类别会直接报错。

## 实现要点

* 新增 `engine/item_catalog.py`：目录读取（按 mtime/size 缓存）+ 展开规则（纯函数，无网络）。
* `engine/config.py`：profile 新增 `inventory.unlock_all` / `unlock_scope` 并校验；
  **在规格构建期**（`to_engine_spec`，即启动/热更新时）把目录展开成库存行，**不进请求热路径**。
* `engine/server.py`：启动与热重载时各打一条日志
  `一键解锁全部物品（仅本机视图）：注入 N 行（目录 M 行；跳过 …）`。
* `gui/pages/inventory.py`：顶栏按钮 + 确认框 + 摘要行显示"一键解锁 全部 N 行"。
  既有「清空全部已添加」按钮**行为未动**（不新增移除按钮）。
* 响应体积：inventory 响应由 ~4.5 KB 增至 ~150 KB（物品多，预期副作用，见下）。

## 验证

* 单测新增 **12 条**（`tests/unit/test_unlock_all.py`）：真实目录展开（>2000 行、去重、排除规则）/
  范围收窄（weapon 精确集合）/ 缺目录兜底 / 规格注入行数一致 / 不与显式行重复 /
  hook 注入 + 二次请求幂等 / `unlock_all` 与 `unlock_scope` 校验。
* 出货 exe 端到端（mock 上游 + 回环探针引擎）：inventory 响应行数 = 基线 55 + 注入 2586，
  含已知武器/外观 mixId；引擎日志出现一键解锁行。
* 全量测试与门禁数字见 CHANGELOG 条目。

## 已知限制 / 注意

* **尚未做游戏内实机确认**（客户端是否完整渲染 2.5k 行、商店/仓库是否变慢）：本版按"客户端侧全部拥有"设计，
  实机表现待验收；若某些类别客户端不认（目录里 `category=unknown` 的 512 行），可先用
  `unlock_scope` 收窄到确定类别。
* 只影响本机视图：服务端仍是事实源；关掉开关 + 应用配置即恢复。
* 目录文件随包分发（`data/catalogs/items.json`），换游戏 build 后目录可能漂移，需随版本更新。
